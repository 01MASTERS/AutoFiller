## Functional Requirements

### FR-1: Chrome Extension Popup UI
- [x] **FR-1.1**: Popup opens when user clicks the extension icon — *Outcome: Validated*
- [x] **FR-1.2**: Toggle switch to enable/disable auto-fill on the current page — *Outcome: Validated*
- [x] **FR-1.3**: LLM provider selector (Ollama / Gemini dropdown) — *Outcome: Validated*
- [x] **FR-1.4**: Status indicator showing current state (idle, analyzing, filling, done, error) — *Outcome: Validated*
- [x] **FR-1.5**: Connection status to backend server (connected/disconnected) — *Outcome: Validated*
- [x] **FR-1.6**: Ollama model name input / dynamic discovery — *Outcome: Validated & enhanced in Phase 10*
- [x] **FR-1.7**: Gemini API key input field (stored in Chrome local storage) — *Outcome: Validated*

### FR-2: Content Script — Form Reading
- [x] **FR-2.1**: Detect when user is on a Google Forms page (`docs.google.com/forms/*`) — *Outcome: Validated*
- [x] **FR-2.2**: Extract all visible text input fields from the form DOM — *Outcome: Validated*
- [x] **FR-2.3**: For each field, extract: label text, placeholder text, aria labels, field type, required flag — *Outcome: Validated*
- [x] **FR-2.4**: Package field metadata into a structured JSON payload — *Outcome: Validated*
- [x] **FR-2.5**: Send field metadata to background worker on user trigger — *Outcome: Validated*

### FR-3: Background Service Worker
- [x] **FR-3.1**: Listen for messages from popup (toggle, config changes) — *Outcome: Validated*
- [x] **FR-3.2**: Listen for messages from content script (field metadata) — *Outcome: Validated*
- [x] **FR-3.3**: Forward field metadata to backend server via HTTP — *Outcome: Validated*
- [x] **FR-3.4**: Receive field→value mappings from backend — *Outcome: Validated*
- [x] **FR-3.5**: Forward mappings to content script for DOM injection — *Outcome: Validated*
- [x] **FR-3.6**: Track and broadcast state changes to popup — *Outcome: Validated*

### FR-4: Backend Server — Profile API
- [x] **FR-4.1**: `GET /health` — Health check endpoint — *Outcome: Validated*
- [x] **FR-4.2**: `GET /profile` — Return the user profile JSON — *Outcome: Validated*
- [x] **FR-4.3**: `POST /autofill` — Accept field metadata, return field→value mappings — *Outcome: Validated*
- [x] **FR-4.4**: Load profile from `profile.json` file on disk at startup — *Outcome: Validated*
- [x] **FR-4.5**: Profile includes: name, email, phone, address, education, work experience, skills, links, custom pairs — *Outcome: Validated*

### FR-5: Backend Server — LLM Gateway
- [x] **FR-5.1**: Unified interface for calling Ollama and Gemini — *Outcome: Validated*
- [x] **FR-5.2**: Ollama: call `POST http://localhost:11434/api/generate` with configurable model — *Outcome: Validated*
- [x] **FR-5.3**: Gemini: call via `@google/generative-ai` SDK with user-provided API key — *Outcome: Validated*
- [x] **FR-5.4**: Prompt engineering: Given a list of form fields + user profile, return a JSON mapping of `{fieldId: profileValue}` — *Outcome: Validated*
- [x] **FR-5.5**: Parse and validate LLM response (must be valid JSON) — *Outcome: Validated*
- [x] **FR-5.6**: Retry on malformed response (up to 2 retries) — *Outcome: Validated*
- [x] **FR-5.7**: Timeout: 30s per LLM call — *Outcome: Validated*

### FR-6: Content Script — Form Filling
- [x] **FR-6.1**: Receive field→value mappings from background worker — *Outcome: Validated*
- [x] **FR-6.2**: For each mapping, locate the DOM element and set its value — *Outcome: Validated*
- [x] **FR-6.3**: Dispatch `input`, `change`, and `blur` events to trigger Google Forms' internal validation — *Outcome: Validated*
- [x] **FR-6.4**: Visual feedback: briefly highlight filled fields (green border flash) — *Outcome: Validated*
- [x] **FR-6.5**: Report fill results back to background worker (success/partial/error per field) — *Outcome: Validated*

## Non-Functional Requirements

- [x] **NFR-1: Performance** — Fill cycle completes in <10s; extension popup renders immediately (<200ms); backend starts in <3s. — *Outcome: Validated*
- [x] **NFR-2: Security** — Profile data remains local; Gemini API key saved in extension storage; CORS restricts API access. — *Outcome: Validated*
- [x] **NFR-3: Reliability** — Handled offline server, invalid API key, 429 quota exhaustion, and unmapped fields with actionable messages. — *Outcome: Validated*
- [x] **NFR-4: Code Quality** — TypeScript strict mode across packages; 71/71 passing Vitest tests; clean build output. — *Outcome: Validated*
- [x] **NFR-5: Developer Experience** — Streamlined `npm run dev`, `npm run build`, `npm test`, and `start.bat`. — *Outcome: Validated*

## User Stories

- [x] **US-1: Basic Auto-Fill Flow** — User opens Google Form, clicks AutoFiller, hits "Fill Form", and fields are populated from profile with green visual confirmation. — *Outcome: Validated*
- [x] **US-2: LLM Provider Selection** — User switches between Ollama (local) and Gemini (cloud) via dropdown with dynamic model discovery. — *Outcome: Validated*
- [x] **US-3: Error Feedback** — Clear diagnostic errors in popup with link to detailed `/logs-ui` dashboard. — *Outcome: Validated*
