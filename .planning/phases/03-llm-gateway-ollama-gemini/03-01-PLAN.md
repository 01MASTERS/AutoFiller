# Plan 03-01: LLM Gateway Interface, Prompt Builder & Response Parser

## Objective

Install `@google/generative-ai` in `backend`, define the `LLMProvider` interface and options, build the prompt engineering service for mapping form fields to profile data, and implement robust JSON response parsing with markdown fence stripping and validation.

## Artifacts this phase produces

### New files
- `backend/src/services/llm/types.ts` — `LLMProvider` interface, provider options, mapping result interfaces
- `backend/src/services/llm/promptBuilder.ts` — System prompt & user prompt generation combining `FieldMetadata[]` and `UserProfile`
- `backend/src/services/llm/responseParser.ts` — Clean markdown code fences and parse JSON string into `Record<string, string>`

### Modified files
- `backend/package.json` — Add `@google/generative-ai` dependency

### New symbols
- `backend/src/services/llm/types.ts`: `LLMProvider`, `LLMOptions`, `LLMProviderError`, `LLMParseError`
- `backend/src/services/llm/promptBuilder.ts`: `buildFieldMappingPrompt()`
- `backend/src/services/llm/responseParser.ts`: `parseLLMJsonResponse()`

<task id="03-01-T3">
<title>Implement robust JSON response parser</title>
<read_first>
- backend/src/services/llm/types.ts
</read_first>
<action>
Create `backend/src/services/llm/responseParser.ts`:
- Function `parseLLMJsonResponse(rawResponse: string): Record<string, string>`:
  - Strips markdown code blocks (` ```json ... ``` ` or ` ``` ... ``` `)
  - Trims whitespace
  - Parses JSON with `JSON.parse`
  - Validates that the result is a plain object where keys and values are strings
  - Throws `LLMParseError` if JSON is invalid or result is not a string key-value map
</action>
<acceptance_criteria>
- `backend/src/services/llm/responseParser.ts` exports `parseLLMJsonResponse`
- Correctly parses plain JSON and markdown-wrapped JSON
- Throws `LLMParseError` on non-JSON input
</acceptance_criteria>
</task>
