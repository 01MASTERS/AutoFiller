# Plan 04-01: Wire LLMGateway & ProfileStore to POST /autofill Endpoint

## Objective

Connect `LLMGateway` and `ProfileStore` in `POST /autofill` endpoint handler. Extract user profile, parse provider options (`provider`, `model`, `apiKey` from body or `x-gemini-api-key` header), execute field mapping via LLM gateway, and return structured JSON mappings with proper error handling.

## Artifacts this phase produces

### Modified files
- `backend/src/types/profile.ts` — Update `autofillRequestSchema` to accept optional `apiKey` in request body.
- `backend/src/routes/api.ts` — Wire `LLMGateway` and `ProfileStore` in `POST /autofill` route handler with status codes (200 OK, 502 Bad Gateway).

<title>Wire LLMGateway and ProfileStore into POST /autofill route</title>
<read_first>
- backend/src/routes/api.ts
- backend/src/services/llm/gateway.ts
- backend/src/services/profileStore.ts
</read_first>
<action>
Modify `backend/src/routes/api.ts`:
- Instantiate default `llmGateway = new LLMGateway()`.
- Update `POST /autofill` handler:
  - Parse request body with `autofillRequestSchema`.
  - Fetch profile using `ProfileStore.getProfile()`.
  - Determine provider (`req.body.provider || 'ollama'`).
  - Determine API key: `(req.headers['x-gemini-api-key'] as string) || req.body.apiKey`.
  - Call `llmGateway.mapFields(provider, fields, profile, { apiKey, model: req.body.model })`.
  - On success: return `200 OK` with `{ status: 'success', mappings }`.
  - Catch `LLMProviderError` / `LLMParseError`: return `502 Bad Gateway` with `{ status: 'error', error: err.message, mappings: {} }`.
</action>
<acceptance_criteria>
- `POST /autofill` invokes `llmGateway.mapFields()` with requested provider and profile data.
- Header `x-gemini-api-key` is correctly forwarded to `llmGateway`.
- Returns HTTP 502 status when gateway throws error.
</acceptance_criteria>
</task>
