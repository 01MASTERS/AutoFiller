# Plan 02-01: Shared Types & Profile Store Endpoint

## Objective

Define domain types (`UserProfile`, `FieldMetadata`, `AutofillRequest`, `AutofillResponse`) in `@autofiller/shared`. Implement `profile.json` loader with Zod validation, automatic sample data fallback, CORS configuration, and `GET /profile` endpoint in `@autofiller/backend`.

## Artifacts this phase produces

### New files
- `backend/src/types/profile.ts` — Zod schema for `UserProfile` validation
- `backend/src/services/profileStore.ts` — Profile file loader, cache, and sample data writer
- `backend/profile.json` — Default sample user profile JSON on disk

### Modified files
- `shared/src/index.ts` — Export `UserProfile`, `FieldMetadata`, `AutofillRequest`, `AutofillResponse`
- `backend/package.json` — Add `zod` and `cors` dependencies
- `backend/src/index.ts` — Add `cors` middleware and `GET /profile` route

### New symbols
- `shared/src/index.ts`: `UserProfile`, `FieldMetadata`, `AutofillRequest`, `AutofillResponse`
- `backend/src/services/profileStore.ts`: `loadProfile()`, `saveProfile()`

<task id="02-01-T3">
<title>Create profile store service with Zod schema validation and sample profile generator</title>
<read_first>
- shared/src/index.ts
- backend/package.json
</read_first>
<action>
Create `backend/src/types/profile.ts`:
- Define `UserProfileSchema` using Zod matching `UserProfile` interface.

Create `backend/src/services/profileStore.ts`:
- Function `getProfilePath()`: uses `process.env.PROFILE_PATH` or defaults to `path.join(process.cwd(), 'profile.json')`.
- Function `getSampleProfile()`: returns realistic sample `UserProfile` data.
- Function `loadProfile()`: checks if `profile.json` exists. If missing, writes sample profile JSON to disk first. Reads file, parses JSON, validates via `UserProfileSchema`. Returns `UserProfile`.

Create initial `backend/profile.json` with sample profile data.
</action>
<acceptance_criteria>
- `backend/src/types/profile.ts` exports `UserProfileSchema`

</acceptance_criteria>
</task>
