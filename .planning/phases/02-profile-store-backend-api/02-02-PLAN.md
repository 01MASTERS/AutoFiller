# Plan 02-02: Autofill Stub Endpoint & API Testing Suite

## Objective

Implement `POST /autofill` stub endpoint in `@autofiller/backend` with Zod validation for `AutofillRequest` payload, returning mock field-to-value mappings. Build comprehensive Vitest test suite covering `/health`, `/profile`, `/autofill`, CORS, and error scenarios.

- `backend/src/types/autofill.ts` — Zod schema for `AutofillRequestSchema` validation

- `backend/src/__tests__/cors.test.ts` — Tests for CORS origin headers

### Modified files

<task id="02-02-T2">
<title>Implement POST /autofill stub endpoint and error handling in backend/src/index.ts</title>
<read_first>
- backend/src/index.ts
- backend/src/types/autofill.ts
</read_first>
<action>
Update `backend/src/index.ts`:
- Add `express.json()` middleware to parse JSON request bodies.
- Add route `POST /autofill`:
  - Validate request body using `AutofillRequestSchema.safeParse(req.body)`.
  - If validation fails, return 400 Bad Request with `{ status: 'error', error: 'Invalid field metadata payload', details: parseResult.error.errors }`.
  - If validation passes, return 200 OK with `AutofillResponse` stub: `{ status: 'success', mappings: {} }`.
- Add global Express error handling middleware to catch unhandled errors and return 500 JSON responses.
</action>
<acceptance_criteria>
- `POST /autofill` with valid field metadata returns 200 with `{ status: 'success', mappings: {} }`
- `POST /autofill` with invalid payload returns 400 Bad Request
- Global error middleware catches exceptions without crashing server
</acceptance_criteria>
</task>
