# Plan 07-01: Background Service Worker & Pipeline Orchestrator

## Objective

Declare background service worker in Manifest V3, build `background.ts` with state machine (`idle` -> `analyzing` -> `filling` -> `done`/`error`), storage persistence, and full orchestration pipeline connecting popup trigger, content script scanning/filling, and backend `/autofill` REST API.

### Modified files
- `extension/src/manifest.ts` — Declare `background.service_worker`

### New files
- `extension/src/background/background.ts` — Background service worker entry point, HTTP client, and state machine

<title>Implement background service worker and state machine</title>
<read_first>
- extension/src/content/contentScript.ts
- .planning/phases/07-background-service-worker/07-CONTEXT.md
</read_first>
<action>
Create `extension/src/background/background.ts`:
- Define `AutofillState = 'idle' | 'analyzing' | 'filling' | 'done' | 'error'`.
- Implement `updateStatusState(state, details)`:
  - Saves `{ currentState: state, ...details }` to `chrome.storage.local`.
  - Broadcasts `{ action: 'STATUS_UPDATE', state, ...details }` via `chrome.runtime.sendMessage`.
- Register `chrome.runtime.onMessage` listener:
  - Action `'TRIGGER_AUTOFILL'`:
    1. Update state to `'analyzing'`.
    2. Query active tab (`chrome.tabs.query({ active: true, currentWindow: true })`).
    3. Send `'SCAN_FIELDS'` message to tab (`chrome.tabs.sendMessage`).
    4. Fetch backend API `POST /autofill` (read backend URL from `chrome.storage.local` key `backendUrl` or default `http://localhost:3456/autofill`).
    5. Update state to `'filling'`.
    6. Send `'FILL_FIELDS'` with `{ mappings }` to active tab (`chrome.tabs.sendMessage`).
    7. On completion, update state to `'done'` with `filledCount` and `failedCount`.
    8. On error at any step, catch and update state to `'error'` with error message.
  - Action `'GET_STATUS'`:
    - Responds with current state from `chrome.storage.local`.
</action>
<acceptance_criteria>
- `background.ts` handles `'TRIGGER_AUTOFILL'` and `'GET_STATUS'` actions.
- Orchestrates scan, backend fetch, fill, and status broadcasts.
</acceptance_criteria>
</task>
