# Plan 08-02: Interactive Popup Logic, Health Check & Settings Persistence

## Objective

Build the TypeScript logic in `popup.ts` to manage settings persistence (`chrome.storage.local`), backend health ping (`/health`), profile preview fetch (`/profile`), provider selector visibility toggles, live status message listener (`STATUS_UPDATE`), and `TRIGGER_AUTOFILL` dispatch.

## Artifacts this phase produces

### Modified files
- `extension/src/popup/popup.ts` — Full popup interactive controller

## Tasks

<task id="08-02-T1">
<title>Implement popup storage binding and provider visibility toggle</title>
<read_first>
- extension/src/popup/popup.html
- extension/src/popup/popup.css
</read_first>
<action>
Update `extension/src/popup/popup.ts`:
- Define storage settings interface `{ provider: 'ollama' | 'gemini', ollamaModel: string, geminiApiKey: string }`.
- Function `loadSettings()`: reads `chrome.storage.local`, populates form inputs, toggles `#ollama-settings` / `#gemini-settings` visibility based on selected provider.
- Function `saveSettings()`: writes current form values to `chrome.storage.local`.
- Add event listeners for `change` / `input` events on `#provider-select`, `#ollama-model-input`, and `#gemini-key-input` to trigger `saveSettings()` instantly.
</action>
<acceptance_criteria>
- Popup loads settings from `chrome.storage.local` on open.
- Toggles provider-specific settings cards cleanly.
- Auto-saves settings on input change.
</acceptance_criteria>
</task>

<task id="08-02-T2">
<title>Implement backend health check, profile fetch, and trigger auto-fill action</title>
<read_first>
- extension/src/popup/popup.ts
- extension/src/background/background.ts
</read_first>
<action>
Update `extension/src/popup/popup.ts`:
- Function `checkBackendHealth()`: fetches `http://localhost:3456/health`, updates `#backend-status-pill` text (`Online` / `Offline`) and CSS class.
- Function `fetchProfile()`: fetches `http://localhost:3456/profile`, updates `#profile-name` and `#profile-email`.
- Function `updateStatusUI(statusDetails)`: updates `#status-banner` text and class based on current state (`analyzing`, `filling`, `done`, `error`).
- Add click listener on `#autofill-btn`:
  - Dispatches `chrome.runtime.sendMessage({ action: 'TRIGGER_AUTOFILL', options: { provider, model, apiKey } })`.
- Add message listener `chrome.runtime.onMessage.addListener`:
  - On `'STATUS_UPDATE'` message, calls `updateStatusUI()`.
</action>
<acceptance_criteria>
- Backend connection status updates dynamically via `/health`.
- Profile details loaded into preview card via `/profile`.
- Auto-fill button sends `TRIGGER_AUTOFILL` message to background.
- Live status updates rendered on status banner.
</acceptance_criteria>
</task>
